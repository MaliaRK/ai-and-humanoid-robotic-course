# Gazebo Setup and Configuration

This chapter provides a comprehensive guide to setting up and configuring Gazebo for humanoid robotics simulation. Gazebo is a powerful physics simulator that provides realistic simulation environments for testing and validating humanoid robot behaviors.

## Introduction to Gazebo

Gazebo is a 3D dynamic simulator with accurate physics, realistic rendering, and convenient programmatic interfaces. It is widely used in robotics research and development for testing algorithms, robot designs, and scenarios without the need for physical hardware.

### Key Features of Gazebo

- **Realistic Physics**: Accurate simulation of rigid body dynamics, contact forces, and collisions
- **High-Quality Rendering**: Detailed 3D visualization with support for lighting, shadows, and textures
- **Sensor Simulation**: Comprehensive support for various sensors (LiDAR, cameras, IMU, etc.)
- **ROS Integration**: Native integration with ROS and ROS 2 for seamless robot simulation
- **Extensible Architecture**: Plugin system for custom sensors, controllers, and world elements

## Installing Gazebo

For humanoid robotics simulation, we recommend using Gazebo Fortress or newer versions. The following installation steps assume you're using Ubuntu 22.04 with ROS 2 Humble:

```bash
# Install Gazebo Fortress
sudo apt update
sudo apt install gz-fortress

# Or install the ROS 2 Humble Gazebo packages
sudo apt install ros-humble-gazebo-ros-pkgs ros-humble-gazebo-ros2-control
```

## Gazebo Architecture and Components

Gazebo follows a client-server architecture with the following key components:

### Gazebo Server (gzserver)

The Gazebo server is the core physics simulation engine that handles:

- Physics simulation calculations
- Collision detection
- Sensor data generation
- World state management

### Gazebo Client (gzclient)

The Gazebo client provides the user interface for:

- 3D visualization of the simulation
- Interactive controls
- Real-time monitoring

### Communication Layer

Gazebo uses the Gazebo Transport protocol for internal communication and can interface with ROS 2 through the `gazebo_ros_pkgs`.

## Basic Gazebo Usage

### Launching Gazebo

To launch Gazebo with an empty world:

```bash
gz sim
```

To launch with a specific world file:

```bash
gz sim -r /path/to/world_file.sdf
```

### Loading a World

Gazebo worlds are defined using SDF (Simulation Description Format) files. A basic world file includes:

- Environment description
- Physics parameters
- Models and their initial positions
- Lighting and rendering settings

## Gazebo Simulator Architecture

The Gazebo simulator architecture consists of several interconnected systems:

### Physics Engine Layer

This layer handles all physics calculations including:

- Rigid body dynamics
- Collision detection and response
- Joint constraints
- Force and torque calculations

### Sensor System

The sensor system simulates various types of sensors:

- **Camera Sensors**: RGB, depth, and stereo cameras
- **Range Sensors**: LiDAR and sonar sensors
- **Inertial Sensors**: IMU and accelerometer data
- **Force/Torque Sensors**: Joint force and torque measurements

### Rendering Engine

The rendering engine provides:

- Real-time 3D visualization
- High-quality graphics rendering
- Lighting and shadow effects
- Camera views and perspectives

## ROS 2 Integration

Gazebo integrates seamlessly with ROS 2 through the `gazebo_ros_pkgs` package, which provides:

- **Message Bridges**: Connect Gazebo topics to ROS 2 topics
- **Service Interfaces**: Control simulation through ROS 2 services
- **Plugin System**: Extend functionality with ROS 2-aware plugins

### Common ROS 2 Interfaces

Gazebo typically exposes the following ROS 2 interfaces:

- `/clock`: Simulation time publisher
- `/tf` and `/tf_static`: Transform data
- Sensor data topics (e.g., `/camera/image_raw`, `/scan`)
- Robot control topics (e.g., `/joint_states`, `/cmd_vel`)
